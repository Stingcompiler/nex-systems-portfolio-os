# stingdev — منصة أعمال لمطور Full-Stack

منصة متكاملة ثنائية اللغة (عربي/إنجليزي) تجمع: موقعًا تسويقيًا، ونظام إدارة محتوى، وإدارة عملاء مصغرة، ومدونة، ونظام أعضاء وتعليقات، ونشرة بريدية وحملات، ولوحة تحكم مخصصة، ونسخة PWA.

## التشغيل

المنصة **وحدة واحدة**: ملف إعدادات واحد، وأمر واحد للتشغيل، ووحدة نشر واحدة. `run.py` هو المدخل الوحيد ولا يحتاج أي حزمة خارجية.

### أول مرة

```bash
python run.py setup
```

ينشئ `.env` من القالب، ويبني البيئة الافتراضية، ويثبّت اعتماديات الطرفين، ويرحّل قاعدة البيانات، وينشئ مجموعات الصلاحيات، ويزرع المحتوى الأولي.

ثم أنشئ حسابك الإداري:

```bash
python run.py manage createsuperuser
```

### التطوير اليومي

أمر واحد يكفي — `runserver` يشغّل Django والواجهة معًا:

```bash
cd backend
python manage.py runserver
```

يفعل الآتي تلقائيًا: Django على `http://127.0.0.1:8000`، وNext.js على `http://localhost:3000` (بلا `npm run dev` يدوي)، ويفتح الصفحة الرئيسية في المتصفح عند الجاهزية، ويوقف الواجهة تلقائيًا عند `Ctrl+C` (بلا عمليات Node يتيمة). لوحة إدارة Django على `/admin/`.

معالجة الأخطاء مدمجة (ويندوز): غياب Node/npm أو `node_modules` أو مجلد الواجهة، أو انشغال المنفذ 3000/8000 — كلها تُبلَّغ برسالة واضحة ويستمر Django. خيارات: `--no-frontend` (Django وحده) و`--no-browser`.

بديل موحّد المخرجات (يضيف عامل المهام أيضًا عبر `--worker`):

```bash
python run.py dev
```

### بقية الأوامر

| الأمر | الوظيفة |
|---|---|
| `python run.py check` | فحوصات Django · الترحيلات المعلّقة · 143 اختبارًا · مخطط OpenAPI · أنواع الواجهة |
| `python run.py build` | بناء الإنتاج (يشغّل الـ API مؤقتًا إن لزم) |
| `python run.py serve` | تشغيل نسخة الإنتاج محليًا |
| `python run.py test` | اختبارات الخلفية وحدها |
| `python run.py manage …` | أي أمر Django |

### كل شيء على منفذ واحد

| المسار | يخدمه |
|---|---|
| `http://localhost:3000/` | Next.js |
| `/api/v1/…` | Django |
| `/api/schema/swagger-ui/` | توثيق الـ API التفاعلي |
| `/django-admin/` | لوحة Django (للطوارئ) |
| `/media/` · `/static/` | ملفات على القرص |

المتصفح لا يعرف عنوان Django إطلاقًا: لا CORS، ولا نطاق فرعي، والكوكيز HttpOnly تعمل بـ `SameSite=Lax`. في الإنتاج يقوم Nginx بنفس التوزيع، فسلوك التطوير مطابق للإنتاج.

### الإعدادات

ملف `.env` واحد في جذر المستودع للطرفين. الخلفية تقرأ كل المفاتيح، والواجهة تقرأ قائمة محددة فقط (`FRONTEND_ENV_KEYS` في `frontend/next.config.mjs`) — مفتاح Django السري وكلمة مرور قاعدة البيانات وبيانات SMTP لا تدخل عملية Node أصلًا.

### النشر

انظر [deploy/README.md](deploy/README.md) — وحدة `systemd` واحدة، وكتلة Nginx واحدة، وسكربت نشر واحد.

## التقنيات

| الطبقة | التقنية |
|---|---|
| Backend | Django 5 · Django REST Framework · SimpleJWT |
| قاعدة البيانات | SQLite (تطوير) · PostgreSQL أو SQLite (إنتاج) |
| المهام الخلفية | django-q2 (وسيط ORM — بلا Redis) |
| Frontend | Next.js 15 (App Router) · Tailwind CSS · TypeScript |
| الحالة | Context API (مصادقة/لغة/ثيم) · TanStack Query (لوحة التحكم) |
| الشبكة | Axios |
| الترجمة | next-intl + حقول `_ar/_en` في قاعدة البيانات |
| الأيقونات والحركة | lucide-react · framer-motion |

بلا Docker — تشغيل محلي مباشر، ونشر تقليدي على VPS.

## المبادئ الحاكمة

1. لا نص ديناميكي داخل الكود — كل ما يراه الزائر من قاعدة البيانات أو ملفات الترجمة.
2. Server Components افتراضيًا في الصفحات العامة.
3. لا رموز في `localStorage` — كوكيز HttpOnly حصرًا في الويب.
4. التحقق مزدوج: الواجهة والـ API.
5. لكل صفحة أربع حالات: تحميل · خطأ · فراغ · محتوى.
6. القسم الفارغ يختفي تلقائيًا.
7. لا صفحة تُنشر بمحتوى رقيق.
8. خصائص CSS المنطقية حصرًا — لا `left/right`.
9. لا ميزة خاصة بمحرك قاعدة بيانات واحد.
