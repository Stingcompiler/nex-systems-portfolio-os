## 2. مبدأ الأصل الواحد (Same-Origin)

القرار المعماري الأهم: **المتصفح لا يعرف إلا نطاقًا واحدًا**.

### في التطوير

أمر واحد يشغّل كل شيء:

```bash
python run.py dev
```

يشغّل Django (8000) والواجهة (3000) وعامل المهام عند الطلب، بمخرجات موحّدة موسومة، وينهي المجموعة كاملة بـ Ctrl+C. الإنهاء يقتل شجرة العمليات لا العملية الأم وحدها — إنهاء `npm` وحده على ويندوز يترك Node يتيمًا يحتجز المنفذ.

وفي `next.config.mjs`:

```js
async rewrites() {
  return [
    { source: '/api/:path*',          destination: `${origin}/api/:path*/` },
    { source: '/django-admin/:path*', destination: `${origin}/django-admin/:path*/` },
    { source: '/media/:path*',        destination: `${origin}/media/:path*` },
    { source: '/static/:path*',       destination: `${origin}/static/:path*` },
  ];
}
```

المتصفح يرى `localhost:3000` فقط.

**تفصيلة الشرطة المائلة:** مسارات Django تنتهي بشرطة، لكن Next يجرّدها من المسار قبل تطبيق إعادة الكتابة، فيصل Django `/api/v1/health` فيردّ بتحويل 301 — وطلبات `POST` لا ينقذها `APPEND_SLASH` أصلًا. الحل شقّان: `skipTrailingSlashRedirect: true` لتعطيل تحويل Next، وإعادة الشرطة صراحةً في وجهة إعادة الكتابة. توحيد مسارات الصفحات انتقل إلى `middleware.ts` حيث يُستثنى `/api` و`/django-admin` أصلًا.

### في الإنتاج

Nginx يوزّع على نفس النطاق:

```
stingdev.com/          →  Next.js (127.0.0.1:3000)
stingdev.com/api/      →  Gunicorn (127.0.0.1:8000)
stingdev.com/admin/    →  Gunicorn (لوحة إدارة Django)
stingdev.com/media/    →  ملفات ثابتة
stingdev.com/static/   →  ملفات ثابتة
```

**منافذ التطوير ولوحة الإدارة:** Django على `8000` والواجهة على `3000` — دائمًا. Django لا يخدم صفحات الموقع؛ فتح `http://127.0.0.1:8000/` يعرض صفحة تعريف بسيطة بروابط لوحة الإدارة وتوثيق الـ API (لا إعادة توجيه إلى منفذ آخر، تفاديًا للالتباس). لوحة إدارة Django على المسار التقليدي `/admin/`، متاحة مباشرة على `http://127.0.0.1:8000/admin/` وعبر الأصل الموحّد على `/admin/`.

### المكاسب

| المكسب | التفصيل |
|---|---|
| لا CORS | لا إعدادات، لا طلبات preflight، لا أخطاء متقطعة |
| كوكيز بسيطة | `SameSite=Lax` كافية — لا حاجة لـ `SameSite=None` ولا لاستثناءات المتصفحات |
| التطوير = الإنتاج | نفس السلوك تمامًا، فلا مفاجآت عند النشر |
| شهادة SSL واحدة | وخادم واحد |

## 3. تدفق الطلبات

### أ. صفحة عامة (مثال: `/ar/services/school-management`)

```
1. المتصفح → Next.js Server
2. Server Component يستدعي getService(slug, locale) مباشرة إلى Django
3. Django يعيد JSON بالحقول محلولة حسب اللغة
4. Next.js يبني HTML كاملًا + JSON-LD + metadata
5. المتصفح يستقبل HTML جاهزًا — لا طلب بيانات من طرفه
```

التخزين المؤقت: `revalidate` بالوقت للصفحات العامة، مع إبطال موجَّه (`revalidateTag`) عند التعديل من لوحة التحكم عبر webhook داخلي.

### ب. شاشة في لوحة التحكم

```
1. المتصفح → Next.js يعيد هيكل الصفحة (بلا بيانات)
2. TanStack Query → Axios → /api/v1/projects/?page=1
3. الكوكي access_token يُرسل تلقائيًا
4. DRF: CookieJWTAuthentication → التحقق من الصلاحية → JSON
5. TanStack Query يخزّن ويعيد الجلب عند الحاجة
```

### ج. تجديد الرمز

```
401 من أي طلب
  → Axios interceptor يوقف الطلبات المتزامنة في طابور
  → POST /api/v1/auth/refresh/  (كوكي refresh_token)
  → كوكيز جديدة + إبطال الرمز القديم (blacklist)
  → إعادة تشغيل الطابور
  → عند الفشل: تسجيل خروج وتحويل إلى /login
```

## 4. المصادقة بالتفصيل

نقاط نهاية واحدة تخدم الويب والموبايل، والتفريق بترويسة `X-Client`.

| | الويب (`X-Client: web` أو غائبة) | الموبايل (`X-Client: mobile`) |
|---|---|---|
| Access Token | كوكي HttpOnly · `Path=/` · 15 دقيقة | في جسم JSON |
| Refresh Token | كوكي HttpOnly · `Path=/api/v1/auth/` · 7 أيام | في جسم JSON |
| السمات | `Secure` (إنتاج) · `SameSite=Lax` · `HttpOnly` | — |
| القراءة | `CookieJWTAuthentication` | `JWTAuthentication` |
| CSRF | مطلوبة على الطرق غير الآمنة | غير مطلوبة |

### فئة المصادقة

`accounts/authentication.py` تحتوي `CookieJWTAuthentication` ترث من `JWTAuthentication` وتقرأ الرمز من الكوكي إن غابت ترويسة `Authorization`. تُسجَّل الفئتان معًا في `DEFAULT_AUTHENTICATION_CLASSES`، فيعمل العميلان بلا تفريع في المنطق.

### حماية CSRF

بما أن الكوكي يُرسل تلقائيًا، نحتاج إثباتًا أن الطلب صادر من موقعنا:

- كوكي `csrftoken` **غير** HttpOnly يُضبط عند تسجيل الدخول.
- كل طلب `POST/PUT/PATCH/DELETE` من الويب يرسل ترويسة `X-CSRFToken` بنفس القيمة (يضيفها Axios interceptor تلقائيًا).
- الخادم يقارن؛ عدم التطابق = 403.
- طلبات الموبايل معفاة (لا كوكيز أصلًا).

### دورة حياة الرمز

- **التدوير:** `ROTATE_REFRESH_TOKENS=True` — كل تجديد يصدر refresh جديدًا.
- **القائمة السوداء:** `BLACKLIST_AFTER_ROTATION=True` — الرمز القديم يُبطل فورًا.
- **الخروج:** إبطال الرمز الحالي + مسح الكوكيز.
- **الخروج من كل الأجهزة:** إبطال جميع رموز المستخدم.
- **تغيير كلمة المرور:** يبطل كل الرموز إجباريًا.

### حماية تسجيل الدخول

- تحديد معدل: 5 محاولات / 15 دقيقة لكل (بريد + IP).
- قفل مؤقت متدرج بعد 10 محاولات فاشلة.
- تسجيل كل محاولة في `LoginAttempt` وفي `AuditLog`.
- عدم كشف وجود البريد من عدمه في رسالة الخطأ.

## 5. المهام الخلفية

`django-q2` بوسيط ORM — لا Redis، لا Docker، عملية واحدة:

```bash
python manage.py qcluster
```

| المهمة | المشغّل |
|---|---|
| إرسال بريد التحقق / استعادة كلمة المرور | عند الحدث |
| إشعار المدير بطلب مشروع / رسالة تواصل | عند الحدث |
| إرسال حملة بريدية (دفعات) | فوري أو مجدول |
| نشر المقالات المجدولة | كل 5 دقائق |
| تذكير بمواعيد متابعة العملاء | يوميًا |
| معالجة الصور (WebP/AVIF + مصغّرات) | بعد الرفع |
| تجميع إحصائيات الزيارات | كل ساعة |
| تنظيف الرموز المنتهية | يوميًا |

**قاعدة:** أي عملية تتجاوز 300ms أو تتصل بخدمة خارجية تُنفَّذ في الخلفية، لا داخل دورة الطلب.

## 6. الوسائط

- التخزين: نظام الملفات المحلي تحت `MEDIA_ROOT`، يقدّمه Nginx مباشرة.
- عند الرفع: تحقق من الامتداد **ونوع المحتوى الفعلي** (magic bytes)، لا من الاسم.
- قائمة بيضاء صارمة: صور (`jpg/png/webp/avif/svg*`)، مستندات (`pdf/docx/xlsx`)، أرشيف (`zip`).
- `svg` يُعقَّم قبل الحفظ (إزالة `<script>` و`on*`) أو يُمنع.
- الملفات المرفوعة تُحفظ باسم مُولّد (UUID)، ويُحتفظ بالاسم الأصلي كبيانات وصفية.
- تُولَّد نسخ WebP ومصغّرات في الخلفية.
- مسار `MEDIA_ROOT` خارج مجلد المشروع، ولا يُنفَّذ منه أي كود.

## 7. الإعدادات والبيئات

```
backend/config/settings/
├── base.py      مشترك
├── dev.py       DEBUG=True · SQLite · بريد للطرفية · مهام متزامنة
├── test.py      تجزئة سريعة · قاعدة في الذاكرة · بريد locmem
└── prod.py      DEBUG=False · PG أو SQLite · SMTP · تقوية أمنية
```

**ملف إعدادات واحد للطرفين:** `.env` في جذر المستودع، غير مُتتبَّع، ومعه `.env.example` موثّق. الخلفية تقرؤه عبر `django-environ`، والواجهة تقرؤه في `next.config.mjs`.

**لكن الواجهة لا تقرأ منه كل شيء.** `FRONTEND_ENV_KEYS` قائمة سماح صريحة بخمسة مفاتيح فقط: عناوين الموقع والـ API وسر إبطال التخزين المؤقت. مفتاح Django السري وكلمة مرور قاعدة البيانات وبيانات SMTP لا تدخل عملية Node أصلًا — وحدة الإعدادات لا تعني وحدة الوصول إليها.

ترتيب الأولوية: متغيّر معرَّف في بيئة النظام يتقدّم على الملف، فتستطيع خدمات systemd والـ CI تجاوز أي قيمة دون تعديل الملف.

في `prod.py`: `SECURE_HSTS_SECONDS` · `SECURE_SSL_REDIRECT` · `SESSION_COOKIE_SECURE` · `CSRF_COOKIE_SECURE` · `SECURE_CONTENT_TYPE_NOSNIFF` · `X_FRAME_OPTIONS=DENY` · `ALLOWED_HOSTS` محدد.

## 8. الأخطاء والمراقبة

- معالج استثناءات مخصص في DRF يوحّد شكل الخطأ:
  ```json
  { "detail": "...", "code": "validation_error", "errors": { "field": ["..."] } }
  ```
- رسائل الخطأ للمستخدم مترجمة حسب `Accept-Language`.
- `Error Boundary` لكل قسم رئيسي في الواجهة + صفحات `error.tsx` و`not-found.tsx`.
- تسجيل منظّم في ملفات دوّارة، وSentry اختياري في المرحلة الأخيرة.

## 9. النشر — وحدة واحدة

بلا Docker. ثلاث خدمات تُدار كوحدة واحدة عبر `stingdev.target`:

```
Ubuntu VPS
├── Nginx                    كتلة خادم واحدة + شهادة Let's Encrypt
└── stingdev.target          وحدة النشر الواحدة
    ├── stingdev-api.service       Gunicorn  →  Django   (127.0.0.1:8000)
    ├── stingdev-web.service       Node      →  Next.js  (127.0.0.1:3000)
    └── stingdev-worker.service    django-q2 →  المهام الخلفية
```

```bash
sudo systemctl start   stingdev.target     # المنصة كاملة
sudo systemctl restart stingdev.target
sudo journalctl -u 'stingdev-*' -f
```

**سكربتات جاهزة في `deploy/`:** `nginx.conf` (كتلة واحدة توزّع المسارات) · `systemd/` (الخدمات الثلاث والوحدة الجامعة) · `deploy.sh` (سحب ← نسخة احتياطية ← ترحيل ← بناء ← إعادة تشغيل ← فحص صحة) · `backup.sh` (قاعدة البيانات والوسائط مع حذف النسخ القديمة).

نسخ احتياطي يومي عبر cron، **ونسخة خارج الخادم** — نسخة على نفس القرص ليست نسخة احتياطية. واختبر الاسترجاع لا الإنشاء فقط.

التفاصيل الكاملة في [`deploy/README.md`](../deploy/README.md).
